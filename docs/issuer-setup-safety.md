# Local issuer setup and emergency disable (pre-activation)

The optional self-hosted issuer is **not approved for normal startup or a public tunnel**. These instructions describe private local provisioning, not an enabled Dot integration. Use the project's `.runtime/node-lts/bin/node`, a trusted local terminal, and a private directory you own (0700) beneath non-group/world-writable ancestors. Do not place state in the repository. Do not enter a password into a shell argument, environment variable, chat, log, or checked-in file.

`node src/workrelay/issuer_setup.mjs init PRIVATE_DIR HTTPS_ORIGIN CLIENT_ID EXACT_HTTPS_REDIRECT` requires a real TTY. Supply only nonsecret, exact operator-chosen OAuth metadata as arguments. It generates an opaque account ID, a persistent RSA-3072 signing key, a random cookie key and a 0600 `issuer.json`; it obtains the human password exclusively through the local hidden TTY prompt in `provisionLocalHuman`. Nothing is provisioned by the automated tests: they use disposable synthetic verifiers. `node src/workrelay/issuer_setup.mjs reference PRIVATE_DIR` prints **nonsecret** bridge references; it never prints the signing key, cookie key or password verifier. Setup refuses existing issuer/session state or unsafe filesystem permissions.

An explicit alternative requiring **no TTY or supplied password** is `node src/workrelay/issuer_setup.mjs init-chatgpt-cimd-generated PRIVATE_DIR HTTPS_ORIGIN /private/path/to/Workrelay-private/login.txt`. Replace the final argument with a private, owner-only delivery-file path appropriate to your system; it is a file **path**, never a password. Prepare the empty private issuer directory and separate delivery directory with mode 0700 and safe non-writable ancestors; do not place `PRIVATE_DIR` in the delivery directory or repository. This command generates 48 random bytes locally, writes only their base64url password into a new mode-0600 delivery file, and writes only the Argon2id verifier and issuer keys to `PRIVATE_DIR` as separate mode-0600 files. It prints status and the delivery **path**, not the value. The destination must not already exist (including symlinks); existing/partial issuer state is refused rather than rotated. Handled failures remove only files created by that invocation. A crash may leave partial private state: inspect it offline instead of blindly retrying. Retrieve the password locally from the owner-only file without pasting it into chat, commands, logs or the repository; never create a public share link. Owner-only filesystem permissions do not establish cloud device sync, confidentiality, or successful mobile access, which require separate user verification.

## Rotation and compromise

`rotate PRIVATE_DIR` is **pre-start only** and requires a local TTY. It refuses any issuer or interaction SQLite database/sidecar. It makes a private 0600 backup before atomically replacing `issuer.json`. The new active JWKS contains **only** the new key; the old signing key is retained solely in the private backup, never published from the rotated issuer. Existing signatures and browser cookies are invalid under a newly started process. This command **does not revoke an active issuer's session, grant, authorization code or refresh token**; it cannot prove an issuer has been stopped. Do not delete a live database to force rotation.

If a key is compromised or access must be disabled: stop the loopback issuer and block its public HTTPS ingress immediately; preserve private mode-0600 backups before edits; deny the affected principal using the bridge's private revocation control; arrange an independently reviewed offline session/grant/refresh-token revocation before restarting with a replacement key. A still-running process may keep its old verifier and signing key in memory, so file replacement alone is not revocation. Do not restore or serve a compromised private-key backup. Quarantine and dispose of backups using local operator policy. There is no automatic key grace period, and no deployed-issuer rotation procedure in this slice.

If initial setup fails after `human.json` is written but before `issuer.json`, keep the issuer disabled, make a private backup, then remove that **new** verifier offline before retrying. If `issuer.json` already exists, stop rather than overwriting it. Neither this setup nor its tests verifies a real tunnel, Dot/mobile flow, or human TTY provisioning.
